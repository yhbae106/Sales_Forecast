# 종합도매 매출 · MBO 예측 대시보드

## 배포
1. ZIP 압축을 해제합니다.
2. 폴더 안의 `index.html`, `styles.css`, `app.js`, `data.js`를 GitHub 저장소 루트에 업로드합니다.
3. GitHub Settings → Pages → Deploy from a branch → `main / root`로 설정합니다.
4. 생성된 GitHub Pages 주소로 접속합니다.

## 초기 데이터
- `종합도매 마감.xlsx`: 2026년 4~7월 업체/전체 매출 추이의 초기 기준값
- `260821_월별.xlsx`: 2026년 8월 21일 기준 월 누계 상세
- `260821_일자별.xlsx`: 2026년 8월 일자별 상세
- 2026년 8월 MBO 기본값: 269.4억 (첨부 마감파일 기준)
- MBO 목표는 **기준월별로 별도 저장**되며 화면에서 수정 가능합니다.

## 월별 업데이트 방법
- **월별 EXPORT 업데이트**: 첫 열/컬럼에 `년월`이 있는 EXPORT 파일을 선택합니다.
- **일자별 EXPORT 업데이트**: `일자` 컬럼이 있는 EXPORT 파일을 선택합니다.
- 같은 월 파일을 다시 올리면 그 월 상세 데이터는 새 파일 기준으로 교체됩니다.
- 여러 월 파일을 한 번에 선택할 수 있습니다.

## 담당자 규칙
- 백제약품 원주 / 영남 → 임인숙
- 유진약품 / 아이팜코리아 → 정직한
- 그 외 → 배영훈

담당자를 먼저 선택하면 업체 선택 목록도 해당 담당자 업체로 자동 제한됩니다.

## 예측 로직
- 기초 예상 마감 = 현재 누계 ÷ 기준일 기대 진행률 (이후 운영범위·익월 이월 가능성 보정)
- 기준일 필요 누계 = 해당 월 MBO × 기준일 기대 진행률
- 당일 필요 매출 = 당일 필요 누계 - 전 영업일 필요 누계
- 순도 = 현재 누계 ÷ 기준일 필요 누계
- 업체별 MBO = 전월 업체 매출 비중으로 전체 MBO 배분
- 과거 일자별 EXPORT가 2개 월 이상 누적되면 `1차 발행 전 / 1~2차 사이 / 2차 발행 후` 구간을 맞춘 뒤 동일 구간 내 영업일 위치의 누계율 평균을 기대 진행률로 사용합니다.
- 주말, 공휴일, 대체공휴일 및 화면에서 입력한 추가 휴무일은 영업일에서 제외합니다.
- 이력이 부족하면 공휴일을 제외한 영업일 경과율을 사용합니다.

## 데이터 보관
- 업로드한 결과는 브라우저 IndexedDB에 저장됩니다.
- 서버로 파일을 전송하지 않습니다.
- 브라우저 초기화/PC 교체에 대비해 `JSON 백업`을 주기적으로 내려받는 것을 권장합니다.

## 외부 라이브러리
- SheetJS: Excel 파일 브라우저 분석
- Chart.js: 차트 렌더링

현재 버전은 GitHub Pages에서 CDN을 통해 위 라이브러리를 불러옵니다. 인터넷 차단 환경에서는 Excel 업로드/차트 기능이 제한될 수 있습니다.

## 마감 운영범위 반영 예측 (v113)
- 과거 확정월의 **1차/2차 수금내역서 발행 위치**를 정렬하고, 주말·공휴일을 제외한 영업일 기준 누계율과 잔여 매출을 예측합니다.
- 월 마감의 통상 운영범위 **230억~270억**을 예측의 사전 기준으로 사용합니다. 실제 매출을 변경하거나 확정 매출을 억지로 범위에 맞추지 않습니다.
- 기본 예측이 270억을 초과하면 초과분을 **익월 이월 가능액(추정)**으로 분리해 당월 예상 마감에 운영상 상한을 반영합니다. 실제 이월 여부는 확인되지 않았습니다.
- 230억 미만이면 같은 진행위치의 과거 잔여 매출과 남은 영업일을 비교해 회복 가능할 때만 230억 달성 시나리오를 반영합니다. 회복이 어려우면 **미달 위험**을 그대로 표시합니다.
- 월초 전월 상한 근접 시 조기 급증을 이월 유입 *가능성*으로만 판단하며, 수금·정산 원천자료 없이는 실제 이월로 확정하지 않습니다.
- 8개 관리업체가 모두 마감 완료되거나 해당 월 영업일이 종료되면 실제 누계를 보여줍니다. 이미 발생한 270억 초과 실적은 줄이지 않습니다.
- 월 MBO가 없더라도 과거 확정 실적이 있으면 마감 예측을 표시할 수 있습니다.

## 자료 확인과 저장 보호 (v117)

- 상단의 **실적 기준**을 펼치면 선택 월의 원본 파일명, 실제 수록 일자, 매출 행 수, 저장된 월 누계 대조 결과를 확인할 수 있습니다. 일부 일자만 추가·교체한 파일은 파일 수록 범위와 월 전체 기준을 구분합니다. 매출 기준일은 매출 행에서 계산하며, 문구·MBO 등 설정을 저장한 날짜와 구분합니다.
- 공용 자료를 읽지 못하면 **이전 저장 자료 · 최신 확인 실패** 또는 **내장 기준자료 · 최신 확인 실패**로 표시합니다. 확인에 실패한 화면에서는 공용 저장을 시작하지 않습니다. 네트워크 읽기와 본문 처리에는 제한 시간을 적용하고, 페이지를 떠나면 진행 중인 초기 조회를 취소합니다.
- 파일을 저장할 때 해당 Git blob과 SHA를 함께 읽고 같은 버전에 대해서만 수정합니다. 동시에 다른 변경이 있으면 최신 원본을 다시 읽습니다. 업로드 대상 월의 매출이나 동일한 설정 항목이 바뀌었으면 덮어쓰지 않고 새로고침을 안내합니다. 다른 월·다른 설정의 변경은 유지합니다.
- 업로드·설정·문구 저장은 순서대로 진행합니다. 저장 후 전체 내용을 다시 읽어 일치해야 성공으로 표시합니다. 응답이 끊긴 PUT 요청은 성공 여부를 알 수 없으므로 자동 재전송하지 않고 먼저 결과를 확인합니다.
- 잘못된 일자·판매처·금액이 있는 Excel 파일은 해당 행을 안내하고 저장하지 않습니다. 파일명은 기준일로 사용하지 않습니다. 전체업체 SKU 접기, 단일업체 상세, 230~270억 예측 기준과 기존 계산은 유지합니다.
- `node scripts/regression-harness.mjs`는 실제 데이터 합계, 기존 업무·화면 규칙, 실제 런타임의 오류·취소·동시 저장·재조회 동작을 확인합니다. GitHub Pages 업로드와 gh-pages 동기화 전에 이 검증을 통과해야 합니다.
